feat(P8): 节点真连探测（TCP）+ 测速框架

探测（internal/agent/probe）
- TCPPing：对节点地址做 TCP 握手测延迟，并发执行但**保持结果顺序与输入一致**
  （主控按 tag 关联，顺序错乱会让日志与前端展示难以比对）
- 支持多次采样取最小值，抖动时更能反映最好情况
- friendlyDialError：把底层错误转成运维能直接看懂的原因
  （"端口拒绝连接（服务未启动或被防火墙拒绝）" 而不是 dial tcp ...: connection refused）
- 测速框架：调用外部测速程序（默认 mihomo），路径与下载地址可配置、
  下载强制 sha256 校验、校验失败绝不落盘；输出原样回传由主控侧解析
  —— 换任何测速程序都不用改 Agent

修复的真实 bug
- 用 `best == 0` 当"无成功样本"的哨兵：环回或极低延迟连接耗时 < 1ms，
  Milliseconds() 得到 0，会把「可达且极快」误判成「不可达」。
  改用独立的 success 标记。

主控（internal/prober）
- 周期性对所有在线服务器驱动探测；探测**由 Agent 执行**
  （主控通常不在节点网络里，直连节点往往不通）
- 目标从数据库推导（服务器地址 + 入站端口），不需手工维护
- 结果落 node_latency：同节点保留最新 + 历史序列

接口
- GET /api/admin/nodes/latency?server_id=  （批量取最新）
- GET /api/admin/nodes/{id}/latency        （单节点历史）
- POST /api/admin/servers/{id}/probe       （立即触发）
- POST /api/admin/probe/all                （全量异步触发）
- 节点列表接口附带 latency，前端无需为每个节点单独请求

测试
- probe 单测 9 组：可达/拒绝/超时、顺序保持、空输入、已取消上下文、
  按延迟排序（不改入参）、错误文案映射、选项默认值
