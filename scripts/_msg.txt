feat(P8): 套餐 + 兑换码 + 内建 MCP 服务端

套餐（迁移 v9）
- packages 表：流量上限 / 时长 / 价格（以分为单位避免浮点误差）/ 节点与服务器上限 / 排序
- ApplyPackage 的续费语义单独说清楚（最容易出错的地方）：
  * 已有未过期的到期时间默认**顺延**，ExtendFromNow=true 才从当前时间起算
  * ResetTraffic 时才清零已用流量
  * DurationDays=0 表示不过期（expire_at=0）

兑换码
- redeem_codes 表：支持批量生成、限定使用次数、有效期、绑定套餐或只给流量/时长
- Redeem 在**同一事务内**「检查 + 自增」，否则并发兑换会把同一张码用超
- 兑换码去掉易混淆字符（0/O/1/I/L）并按 4-4-4-4 分组，便于口述与抄写
- 失败统一返回"无效或已用尽"，不区分"不存在"与"用尽"，避免被枚举

MCP 服务端（internal/mcp）
- streamable-HTTP，POST /mcp 处理 JSON-RPC 2.0
- 方法：initialize / tools/list / tools/call / ping / notifications
- 11 个工具：list_servers、create_server、list_nodes、create_inbound、
  apply_xray_config、list_users、create_user、get_traffic、
  list_announcements、dispatch_task、get_overview
- **权限与账号完全一致**：AdminOnly 工具对普通用户既不出现在 tools/list，
  调用时也返回 isError；鉴权复用主控的接口令牌
- 工具内部错误按规范表达为 isError 结果而不是 JSON-RPC 错误 ——
  这样 AI Agent 能看到错误内容并自行调整，而不是整轮对话失败
- GET /mcp 明确 405（未实现 SSE）而不是 404，客户端据此能区分
  "服务在但不支持该能力" 与 "地址写错了"
- create_inbound 把传输/安全层的嵌套参数完整暴露：
  少一个字段会在生成 Xray 配置时才报错，那时 AI 已经走远了好几轮
